What Is Claucraft?

A Windows desktop shell for running and managing multiple Claude Code sessions at once.

Claucraft is an MDI (multiple-document-interface) terminal application: every Claude Code session runs inside its own floating terminal window, tiled or cascaded alongside file editors, diagram viewers and memory panels, all within one project-aware shell. It talks to the same claude CLI you already use — Claucraft does not replace it, it wraps it with project management, session history, git tooling and layout features built around running several sessions side by side.

Claucraft is an unofficial, independent project, not affiliated with, endorsed by, or sponsored by Anthropic. Claude and Claude Code are trademarks of Anthropic, PBC. Claucraft does not bundle Claude Code; it runs the copy you installed, signed in with your own account.

Claucraft is aimed at the case none of the others cover well: juggling several active Claude Code sessions — different projects, different worktrees, different tasks — without losing track of which terminal is which, or wiring up your own tmux/window-manager setup to do it.

Toolbar: Project & Session

The panel at the top of the window, above everything else.

The Project row holds a folder combo box for choosing the project you are working in. Type or paste a path directly, or click the folder icon next to it to open a picker (New Project) — the same action available from the welcome page.

The Session row lists Claude Code sessions previously recorded for the selected project, newest first, with their timestamp and a short title. Selecting one enables Resume, which reopens that conversation in a new terminal window. The search icon next to the combo opens Manage Sessions, a searchable list for projects with many saved sessions.

New Session starts a fresh Claude Code conversation. Right-click it (or open its context menu) to toggle New Session (Worktree): when enabled, new sessions are started in their own git worktree, so two windows never edit the same files at once — Resume always reopens in the original project folder, where the session's history lives.

The same menu lists execution targets beyond the local machine: installed WSL distros, recent and ~/.ssh/config SSH hosts, and a free-form host:/path entry. The CLI is then launched through wsl.exe or ssh.exe instead of directly. WSL sessions read their transcript over \\wsl.localhost, so Chat View works for them too; SSH sessions stay in the raw terminal view, since their transcript lives only on the remote host. Remote sessions are left out of saved workspaces.

Scheduled Tasks..., also on the New Session menu, opens a dialog for starting a session automatically in a chosen project with a given prompt — once, every day, or every N minutes — for as long as Claucraft is running. A slot that falls more than 30 minutes behind is skipped rather than caught up.

A model and effort level can be pinned for every new session (Claude only) instead of switching mid-conversation, which would throw away the prompt cache. That choice carries across new windows, restores and launches.

Activity Bar

The narrow strip of icons on the left edge of the window.

Each icon switches the side panel shown next to it, top to bottom:

  • Explorer (Ctrl+Shift+E) — the current project's file tree.
  • Source Control (Ctrl+Shift+G) — git status and actions for the project.
  • Windows — a list of every open terminal, editor, diagram and memory window.
  • Chat View — toggles the active window between its raw terminal and the bubble-based conversation view; see Chat View.
  • Snippets — reusable text blocks you can insert into a session.
  • Slash Commands (Ctrl+/) — browse and insert available slash commands.
  • Extensions — installed MCP servers, skills and plugins.
  • Memory (Ctrl+Shift+M) — Claude's auto-memory notes for this project.
  • Diagram Viewer — appears once a session has produced one; renders Mermaid/graph output from a session inline.

A second group sits at the bottom of the bar:

  • Compact — runs /compact against the active session.
  • Cost — token usage and spend for the current session and plan.
  • Settings — application preferences, grouped by topic.

Explorer

Shows the selected project's folder tree. Right-click a file or folder for common actions (open, reveal, rename, delete, and similar). Double-clicking a file opens it in a floating editor window inside the MDI area — see MDI Terminal & Editor Windows. Editor windows show Save (Ctrl+S) and Close buttons on their own title bar.

Dragging a file from the explorer onto a terminal window inserts a reference to it in the prompt input, prefixed with @. Files inside the working folder are inserted as a relative path, and files outside it as an absolute path — the same format you get by picking one from the @ completion popup. Ctrl+click or Shift+click selects several files or folders at once, and dragging that selection drops every path in as its own @ reference in one go.

Snippets

Stores short pieces of text — prompts, commands, boilerplate — that you reuse across sessions. Snippets are kept per user, not per project, so the same list follows you between projects. Use the panel's search box to filter by name or content, then insert one into the active terminal.

Windows Panel

Lists every window currently open in the MDI area — terminal sessions, editor tabs, diagram viewers and memory panels — regardless of which are on-screen at the moment. Selecting an entry brings that window to the front, which is the fastest way to find a session buried behind others in Tile or Cascade layouts.

This panel also includes Agent View: background sessions started with claude agents are listed under the window that dispatched them, along with their state, what they're currently waiting on, and whether the process is still alive. This is read directly from ~/.claude/jobs rather than by invoking the CLI, so the panel's 700 ms refresh cycle stays free. The same panel also shows a session's in-flight subagents (label, type, model, depth) while they run.

Memory Panel

Reads Claude Code's auto-memory notes for the active project (~/.claude/projects/<project>/memory/) and lists them grouped by note type. A search box filters across the whole set, and MEMORY.md — the index Claude itself loads every session — is shown as a table of contents. Opening a note also shows which other notes link to it (backlinks) and any links inside it that point to a note not written yet. The panel is read-only; notes are written by Claude Code itself, not edited here.

Settings

Grouped into category boxes: language, font family and size, host shell, initial prompt, theme, notifications, checkpoints, live status, commit message language, plan tier, launch model and effort, AI provider executable and argument templates, and a shortcut to the .claude folder. Most settings apply immediately; a few — like the AI provider — apply to new sessions only.

MDI Terminal & Editor Windows

The main working area, filling the rest of the window.

Each Claude Code session runs in its own floating terminal window inside this area, alongside any file editor, diagram or memory windows you have open. Drag a window's title bar to move it, or drag its tab in the window strip to reorder or pop it into its own top-level window. Windows can be arranged automatically (see below) or positioned freely.

Closing a terminal window ends that Claude Code process; the session itself is preserved and can be reopened later from Session → Resume.

Window Strip Toolbar

The horizontal strip directly above the MDI area lists a tab for every open window in this shell and lets you switch between them. A session tab's context menu includes Start Remote Control, which sends /remote-control to the CLI so the session can be continued from another device. The icon buttons on the strip's right edge control layout:

  • Tile — arrange all windows in an even grid.
  • Tile Horizontally / Tile Vertically — stack windows in rows or columns.
  • Full View — maximize the active window, hiding the others.
  • Workspaces — save or restore a named window arrangement; see Saved Workspaces.
  • Help — the button you used to open this page.

Manually resizing or moving a window switches the shell out of its current automatic layout mode into a custom one, which is preserved until you pick a layout button again.

Saved Workspaces

A workspace is a named snapshot of which windows are open and how they are arranged. Use Save Workspace As… from the Workspaces dialog to capture the current layout, and select a saved entry to restore it later — useful for switching between different working contexts within the same project without rebuilding the layout each time.

Chat View

A desktop-app-style view of the session, an alternative to the raw terminal.

Click the Chat View icon in the activity bar to switch the active window between its raw terminal and Chat View, which renders the session's JSONL transcript as message bubbles instead of scrollback. The choice is kept separately for every window and survives restores.

Tool Call Details

Expanding a tool group shows each call: a shell command with its output, an Edit or Write as a coloured diff, Read/Grep/Glob with the targets and a result excerpt, and anything else as its input JSON and result. The model's thinking and the narration between tool calls are shown as well. Clicking a file name a tool touched opens that file in an editor window.

Answering the CLI

Permission prompts, plan approval, menus such as /model, and AskUserQuestion forms all appear as interactive cards in the conversation; the answer is sent to the CLI as the same key presses you would type at its own prompt.

Composer

The input card at the bottom sends prompts and accepts @ file completion and / command completion (↑/↓, Tab, Enter, Esc). Clipboard images (Ctrl+V or Alt+V) and pasted or dropped image files go to a thumbnail strip above the input rather than being inserted as text; click a thumbnail to view it full size, or its × to remove it, and the images go out with the prompt. When the CLI suggests a next prompt, it appears as the input's placeholder text — press Tab to pull it into the box, or press Enter on an empty box to send it as-is.

Working Spark, Stop & Send Queue

A spark animates next to a Stop button while the session is working. A prompt sent mid-turn waits as a removable chip and is sent once the turn ends; pressing Stop puts any queued prompts back into the input box instead of discarding them.

Edit & Rewind

Hovering a previous prompt shows Edit and Rewind. Both drive the CLI's /rewind to return the conversation to that point; Edit also puts the original text back into the input box so it can be changed before resending.

Tasks & Subagents

A strip under the title rebuilds Claude's task checklist from TodoWrite, TaskCreate and TaskUpdate calls, and lists every Agent call made during the session. A subagent that has its own transcript opens in place of the main conversation, with a bar to go back to it.

Find (Ctrl+F)

Highlights every message containing the search text. Enter / Shift+Enter or F3 step forward and backward through the matches.

Side Pane

A resizable pane next to the conversation offers two tabs only: Terminal, the same session's live terminal, and Preview, an embedded WebView2 browser with an address bar, back, reload and open-in-browser controls. When a localhost address shows up in the terminal output, Preview offers it as a one-click suggestion.

Source Control Panel

A focused git client for the active project, opened from the activity bar (Ctrl+Shift+G):

  • Fetch — checks what is new on the remote without changing any local files.
  • Pull — brings the remote's commits into the current branch and replays yours on top.
  • Push — sends local commits to the remote.
  • Merge — brings another branch's work into the branch you are on.
  • Branch menu — switch, create or delete branches. A branch checked out in another worktree is greyed out here, with the reason and the worktree it is in.

Before a push, an optional risky files check scans changed files for credentials, machine-local settings, build output and oversized files. A commit message can be generated by the AI in either English or Japanese, set independently of the app's display language. Pushing a repository that has no remote yet opens an owner / name / description / private dialog and creates it on GitHub with gh repo create. Common git failures get a localized explanation shown above git's own output instead of a bare error message.

Open pull requests show a coloured dot for their combined CI check status, refreshed once a minute while the panel is open. Expanding a PR lists its failing checks and every review, conversation and line comment, each with a button that hands the comment to the AI to fix.

The panel also includes a commit graph for visualizing branch and merge history, with each branch's commits drawn in its own colour and a button to create a tag on any commit.

Status Bar & Live Status

The strip along the bottom of the window.

Shows live information for the active session:

  • Mode badge — the assistant's current mode; click it, or press Shift+Tab, to cycle modes.
  • Context meter — how much of the context window is used before an automatic compact; clicking it runs /compact.
  • Model / Effort — the model and reasoning effort answering in this session. Changing either sends the corresponding command to the terminal, and also updates the default used for new sessions. The model list learns each model line's newest version from recent transcripts, so it does not fall behind when a new model ships. Switching model or effort mid-conversation compacts first when there is enough context worth saving, rather than throwing the prompt cache away silently.
  • Rate limits — usage against the plan's 5-hour and 7-day metering windows, with time until each resets. Claude sessions started from Claucraft get a status line that saves the rate_limits Claude Code itself reports (Pro/Max plans, after the first reply); a status line of your own keeps showing. Get rate limits from Claude Code under Live status turns this off, together with the readout. While it is on, Claude Code hides its footer key hints such as "? for shortcuts". A claude_usage_cache.json your own script leaves in the temp folder is read as a fallback. Claucraft never uses your Claude sign-in itself.

An idle session approaching its prompt-cache expiry shows a "compact now" banner, since the next message would otherwise re-read the whole conversation at full price.

Slash Commands & Command Palette

The Slash Commands panel (Ctrl+/) lists every command available to the active session — built-in, project-defined and user-defined — and inserts the selected one into the terminal. The Command Palette provides quick, searchable access to app-level actions (layouts, panels, dialogs) without needing to know their location in the UI.

Shortcuts & Setup Doctor

Press F1, or use the Keyboard Shortcuts button in Settings, to open a cheat sheet of every shortcut in the app. Setup Doctor, also in Settings, checks that the AI CLI, git and any other required tools are installed and signed in, and reports what — if anything — needs attention.

Notifications & Updates

Toast notifications surface events such as a long-running turn finishing while its window is in the background. An update banner appears in the bottom-left corner when a new release is available, with an option to view the release notes or apply the update in place. Checkpoints, reachable from Settings, list saved states you can jump back to within a session.

Extensions

Lists the MCP servers, skills and plugins currently installed for the active AI provider, and whether each is available to the session. Use the refresh button after installing or updating one outside the app. Double-clicking a skill runs it.

MCP servers can be managed from here too, through claude mcp: add one as stdio or http, choosing its scope (local, project or user), remove one, or check its connection status — all without leaving the panel.

Launch Profiles & Worktrees

Launch profiles are flags applied automatically to every new session — for example, bounding context length, which is what most directly lowers cost. Configure them from Settings. Worktree mode (toggled from the New Session context menu) starts a session in its own git worktree instead of the shared project folder, so two windows can work on the same repository without editing the same files at the same time.
